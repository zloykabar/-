Модель OSI

OSI (Open Systems Interconnection) — эталонная сетевая модель, описывающая, как данные передаются от приложения одного устройства к приложению другого. Модель разбивает процесс на 7 уровней, каждый из которых отвечает за свою часть работы.

Зачем нужна модель OSI

  • Независимо разрабатывать и заменять протоколы на каждом уровне.
  • Понимать, на каком уровне возникает проблема.
  • Стандартизировать оборудование и ПО от разных производителей.

7 уровней модели OSI

7Прикладной (Application)

Обеспечивает взаимодействие сети и пользователя. Интерфейс для браузера, почтового клиента, мессенджера.

Протоколы: HTTP, HTTPS, FTP, DNS, SMTP, DHCP, SSH
Устройства: Gateway, Proxy
6Представления (Presentation)

Преобразует данные в формат, понятный приложению: кодировка, сжатие, шифрование.

Примеры: SSL/TLS, JPEG, MPEG, ASCII, Unicode
5Сеансовый (Session)

Устанавливает, поддерживает и завершает сеанс связи между двумя приложениями.

Протоколы: RPC, NetBIOS, SIP, L2TP, PPTP
4Транспортный (Transport)

Обеспечивает надёжную (или быструю) доставку данных. Разбивает на сегменты, управляет потоком, использует порты.

Протоколы: TCP, UDP, SCTP
PDU: сегменты / датаграммы
3Сетевой (Network)

Определяет путь передачи данных между разными сетями. Логическая адресация (IP) и маршрутизация.

Протоколы: IP, ICMP, IPsec, OSPF, BGP
PDU: пакет
Устройства: маршрутизатор, L3-switch
2Канальный (Data Link)

Передаёт данные между соседними устройствами в одной сети. MAC-адреса, контроль ошибок.

Протоколы: Ethernet, Wi-Fi, PPP, VLAN
PDU: кадр
Устройства: коммутатор, мост, точка доступа
1Физический (Physical)

Передаёт биты (0 и 1) по физической среде: кабелю, оптоволокну, радиоволнам.

Среда: витая пара, оптоволокно, радиоволны
PDU: биты
Устройства: концентратор, репитер, кабель

Как запомнить порядок уровней

Сверху вниз (7→1): «Прикладной, Представления, Сеансовый, Транспортный, Сетевой, Канальный, Физический»
Мнемоника: «Прилежный Программист Сделал Тестовую Сеть Крутой Фишкой»
Практическая польза: если у вас «не открывается сайт», начните с физического уровня, затем канального (MAC, коммутатор), сетевого (ping, IP), транспортного (порт) и только потом прикладного (DNS, HTTP).

Общая информация

Базовые понятия, которые нужны для понимания любой сети.

ПонятиеОпределениеПример
IP-адресУникальный числовой адрес устройства в сети.192.168.1.10
Маска подсетиОпределяет, какая часть IP-адреса относится к сети.255.255.255.0 = /24
ШлюзIP устройства, через которое компьютер выходит в другие сети.192.168.1.1
DNSСистема, преобразующая имена в IP-адреса.google.com → 142.250.74.14

Как посмотреть свои параметры

Windows: ipconfig /all
macOS: ifconfig или ipconfig getifaddr en0
Linux: ip addr или ifconfig -a

Диапазоны частных адресов

  • 10.0.0.0/8 — крупные корпоративные сети
  • 172.16.0.0/12 — средние сети
  • 192.168.0.0/16 — домашние и офисные сети

Маска подсети — подробнее

IP:    192.168.1.10   → 11000000.10101000.00000001.00001010
Маска: 255.255.255.0  → 11111111.11111111.11111111.00000000
                         └──────── сеть ───────┘└─ хост ─┘
Сеть:                   192.168.1.0
Broadcast:              192.168.1.255
Хосты:                  192.168.1.1 … 192.168.1.254 (254 шт.)

Как считать в уме

  • Количество адресов = 2(32 − префикс)
  • Используемых хостов = 2(32 − префикс) − 2
  • /24 → 256 адресов → 254 хоста
  • /30 → 4 адреса → 2 хоста

Маска с подстановочным знаком (Wildcard)

Формула: wildcard = 255.255.255.255 − маска
Пример: 255.255.255.0 → 0.0.0.255

Диагностика сети

Ping — проверка доступности

Windows: ping 8.8.8.8
macOS / Linux: ping 8.8.8.8 (остановить Ctrl+C)

Traceroute / Tracert

Windows: tracert google.com
macOS / Linux: traceroute google.com

NSLookup / Dig

Все ОС: nslookup google.com
macOS / Linux: dig google.com

Netstat / SS

Windows: netstat -an
macOS / Linux: netstat -tuln или ss -tuln

Проверка порта

Windows (PowerShell): Test-NetConnection google.com -Port 443
macOS / Linux: nc -zv google.com 443

Сброс сетевых настроек

Windows: ipconfig /flushdns, ipconfig /release + ipconfig /renew
macOS: sudo dscacheutil -flushcache
Linux: sudo systemctl restart NetworkManager
Если ping 8.8.8.8 работает, а сайты не открываются — проблема почти наверняка в DNS.

HTTP vs HTTPS

Определения

HTTP — протокол передачи гипертекста, данные передаются в открытом виде.

HTTPS — тот же HTTP, но поверх шифрования TLS/SSL.

Ключевые отличия

ПараметрHTTPHTTPS
Порт по умолчанию80443
ШифрованиеНетДа, TLS/SSL
Защита от перехватаУязвимЗащищён
Аутентификация сервераНетДа, через сертификат
Целостность данныхНе гарантируетсяКонтролируется
Современный статусУстаревшийСтандарт

Что даёт HTTPS

  • Шифрование — данные не видны провайдеру и злоумышленнику.
  • Аутентификацию — сертификат подтверждает подлинность сайта.
  • Целостность — данные нельзя подменить по пути.

Проверка сертификата

Все ОС: curl -v https://example.com
OpenSSL: openssl s_client -connect example.com:443 -servername example.com

Серверы

Что такое сервер

Сервер — компьютер или программа, предоставляющая ресурсы и сервисы клиентам по сети.

Типы: веб-сервер (Nginx, Apache), файловый (SMB, FTP), почтовый, БД (MySQL, PostgreSQL), DNS.

Основные порты

СервисПортНазначение
HTTP80Веб без шифрования
HTTPS443Веб с шифрованием
SSH22Управление Linux
RDP3389Удалённый рабочий стол
MySQL3306База MySQL
PostgreSQL5432База PostgreSQL
DNS53Разрешение имён
SMB445Сетевые папки Windows

Как подключиться

Linux / macOS: ssh user@server_ip
Windows: ssh user@server_ip или PuTTY

Для Windows-серверов — mstsc (RDP) или Microsoft Remote Desktop на macOS.

Проверка доступности

Пинг: ping server_ip
Порт (macOS / Linux): nc -zv server_ip 443
Порт (Windows): Test-NetConnection server_ip -Port 443
HTTP: curl -I https://server_ip

Просмотр портов на сервере

Linux: ss -tuln / netstat -tuln
Windows: netstat -an

Базовые принципы

  • Не работайте под root — используйте sudo.
  • SSH-ключи безопаснее паролей: ssh-keygen → ssh-copy-id.
  • Обновляйте систему: sudo apt update && sudo apt upgrade.
  • Проверяйте логи: journalctl -xe, tail -f /var/log/syslog.

Маршрутизатор

Что такое маршрутизатор

Маршрутизатор — устройство, которое соединяет разные сети и направляет пакеты на основе таблицы маршрутизации.

Основные команды (Cisco IOS)

ЗадачаКоманда
Привилегированный режимenable
Режим конфигурацииconfigure terminal
Таблица маршрутизацииshow ip route
Статический маршрутip route <сеть> <маска> <шлюз>
Сохранить конфигcopy running-config startup-config
Интерфейсыshow ip interface brief
VLANshow vlan brief

Порты и интерфейсы

Cisco: show interfaces status, show ip interface brief
MikroTik: /interface print, /ip address print
Linux: ip link show, ip addr, ss -tuln
Windows (RRAS): Get-NetAdapter, Get-NetIPAddress

Настройка VLAN (Cisco)

vlan 10
 name Office
 exit

interface FastEthernet0/1
 switchport mode access
 switchport access vlan 10
 exit

show vlan brief
show interfaces status

Транк (несколько VLAN)

interface GigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 exit

MikroTik: VLAN через bridge

/interface bridge vlan
add bridge=bridge1 tagged=ether1 untagged=ether2 vlan-ids=10

/interface bridge port
set [find interface=ether2] pvid=10

Linux: VLAN через iproute2

sudo ip link add link eth0 name eth0.10 type vlan id 10
sudo ip addr add 192.168.10.1/24 dev eth0.10
sudo ip link set eth0.10 up
Команды VLAN зависят от производителя. На домашних роутерах VLAN обычно настраивается через веб-интерфейс.

IP-телефония (VoIP)

IP-телефония — передача голоса по сетям с протоколом IP. Голос оцифровывается, разбивается на пакеты и передаётся по общей сети.

Как это работает

  1. Регистрация: телефон отправляет REGISTER SIP-серверу.
  2. Установка соединения: клиент отправляет INVITE.
  3. Передача голоса: по протоколу RTP в UDP-пакетах.

Ключевые протоколы

ПротоколНазначениеПорт
SIPСигнализацияUDP/TCP 5060, TLS 5061
RTPПередача голоса и видеоUDP 16384–32768

SIP-методы

МетодНазначение
REGISTERРегистрация абонента
INVITEИнициирование вызова
ACKПодтверждение ответа
BYEЗавершение сессии
OPTIONSПроверка доступности
CANCELОтмена вызова

Диагностика SIP

Linux: sudo apt install sipsak
macOS: brew install sipsak
Windows: через WSL, как для Linux
sipsak -v -s sip:sip.example.com

Успех — SIP/2.0 200 OK или 200 Keepalive.

IP-телефония на Cisco

enable
configure terminal

dial-peer voice 10 voip
 description To-SIP-Provider
 destination-pattern 9T
 session protocol sipv2
 session target ipv4:203.0.113.50
 codec g711ulaw
 exit

Особенности через NAT

  • Включите поддержку NAT в УАТС (Asterisk/FreePBX).
  • Пробросьте порты SIP (5060) и RTP (10000–20000) на внутренний IP УАТС.
SIP чувствителен к задержкам и потерям пакетов. Для качественной связи используйте QoS.
